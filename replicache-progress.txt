## Task 1: Verify row-version triggers fire on INSERT + UPDATE with distinctness guard

Issues found and fixed:
  1. packages/db/src/migrations/0033_sync_row_version_triggers.sql — `bump_row_version()` had no no-op guard. Combined with `lifecycle_dates.updatedAt` using Drizzle's `$onUpdate(() => new Date())`, every `.update()` call auto-bumps `updated_at`, so even a semantic no-op UPDATE (e.g. momentUpdate called twice with identical payload) would satisfy a vanilla `WHEN (OLD.* IS DISTINCT FROM NEW.*)` clause and bump `row_version`, emitting a redundant `put` on the next CVR diff. Fixed by adding migration 0038_sync_row_version_distinctness_guard.sql which replaces the function with a body-level guard: compare `to_jsonb(NEW) - 'row_version' - 'updated_at'` vs OLD's equivalent, and short-circuit when they're IS NOT DISTINCT FROM. Exclude the metadata columns so Drizzle-generated timestamp bumps don't count as a change. Also updated _journal.json (idx 38) and copied 0037_snapshot.json → 0038_snapshot.json (schema unchanged; new snapshot id + prevId chain).

Issues noted (no fix needed):
  1. packages/db/src/migrations/0033_sync_row_version_triggers.sql:10-22 — Trigger is `BEFORE UPDATE` only (no INSERT). Confirmed intentional and correct: the in-migration comment explains it, and pull.ts step 6 relies on presence-in-current vs presence-in-prev (not row_version) to detect new rows. A new row's row_version defaults to 0, and the CVR diff emits `put` because `prevSnapshot.{table}[id]` is undefined, independent of row_version value. Adding `BEFORE INSERT` would be redundant.
  2. packages/api/src/modules/replicache/pull.ts:141-183 — Pull publishes three entity types: assetMoments, assetComments, notifications. All three schemas have `row_version integer NOT NULL DEFAULT 0` (comments.ts:42-43, moments.ts:54-55, notifications.ts:46) and all three have a bump trigger (0033 for moments/comments, 0037 for notifications). Cross-reference complete — no synced entity is missing a trigger.
